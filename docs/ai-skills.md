# Marginote AI Skills 开发者规格

Marginote 的内置 AI 不直接根据模型返回值调用任意业务函数。每轮请求会先被本地纯逻辑规划器分类，再把本轮允许的工具集合同时用于 Prompt 展示和运行时校验。

## 分层与职责

1. `shared/js/tool-policy-core.js`：业务工具的唯一策略注册表，声明助手/CLI 暴露面、读写等级、事务和工作目录投影。
2. `shared/js/assistant-skill-core.js`：组合原子工具，声明 Skill、动作能力、Prompt 规则和步骤预算。
3. `shared/js/assistant-core.js`：识别意图与动作，结合附件生成本轮执行计划；同时提供检索排序、历史窗口、响应解析、工具预算、结果收集、token 汇总和错误降级等纯函数。
4. `shared/js/assistant-prompt-core.js`：唯一构建 system 规则与不可信本地上下文，限制附件、检索、最近笔记和相关记忆数量。
5. `shared/js/ai-provider-core.js`：统一 OpenAI 兼容请求、Header、普通/SSE 响应、原生工具调用、token 用量和重试边界。
6. `shared/js/assistant.js`：桌面业务工具实现、模型调用、流式展示、删除确认和结果收据。
7. `extension/js/assistant.js`：扩展端工具实现和模型调用；共享纯逻辑核心由 `shared/js/` 生成并受 CI 校验。

依赖方向固定为：工具策略 → Skill → 助手核心 → 端侧实现。核心层不得访问 DOM、存储或模型接口。

## 内置 Skill

| Skill | 写入策略 | 主要用途 |
|---|---|---|
| `note_query` | 只读 | 搜索、读取、摘要、统计和导出笔记 |
| `note_write` | 确认式写入 | 创建、编辑、整理或删除笔记 |
| `todo_query` | 只读 | 搜索、读取和汇总待办 |
| `todo_write` | 确认式写入 | 创建、更新、完成或删除待办 |
| `memory` | 仅明确请求 | 保存、查询或删除持久记忆 |
| `general` | 有限写入 | 通用问答、简报、番茄钟及明确的轻量记录 |

写入 Skill 不是固定开放其全部工具。规划器还会识别 `capture`、`edit`、`organize`、`complete`、`delete` 和 `batch` 动作，只组合本轮必要工具。批量工具使用条件组合，例如只有 `organize + batch` 才开放 `batch_move_notes`，不会同时开放批量删除。复杂条件可以位于动作和对象之间，例如“删除所有标题为空或者内容为空的笔记”仍会稳定识别为 `delete + batch`。

复杂查找与条件清理建立在通用结构化查询上，而不是为某一句话增加专用工具。`query_notes` 支持全文主题、标题/正文/笔记本/标签/类型/收藏/长度/时间等字段，组合通用比较操作符，并返回精确总数和分页结果；`delete_notes_by_query` 在用户确认后处理冻结的查询结果，不依赖模型枚举 ID，也不受普通搜索单页数量限制。确认后会再次执行同一查询：新出现的匹配项不会被追加删除，不再符合条件的笔记会跳过。

默认交互优先覆盖三个核心场景：用户直接问“项目最终决定了什么”时，即使没有“查找/搜索”等动词也进入 `note_query` 并先做本地预检索；“把这段记下来”也会先搜索相似主题，同一主题可靠命中时优先 `append_to_note`，没有可靠匹配才 `create_note`，“写进项目复盘笔记”则进入目标检索与追加；只有“请记住/保存到记忆”等明确表达才开放 `save_memory`。连续对话会把上一轮成功写入的目标类型和 ID 放回有界历史，便于“再补充一点”继续写入同一篇。单独出现“任务调度”或“提醒功能”不会误切到待办域，只有个人任务、截止或提醒语境才查询待办。

## 安全与上下文约束

- 模型只能执行本轮 `allowedToolNames` 中的工具；Prompt 不是权限边界。
- 删除类工具除白名单外还必须通过用户确认；条件删除的确认文案必须展示结构化条件数量、组合方式和精确命中数量。
- 普通对话不能写入持久记忆；只有明确的记住/查询记忆/删除记忆请求才开放相应工具。
- 笔记、待办、检索结果和记忆作为不可信的 `user` 上下文发送，不拼入 system 消息。
- 普通请求只带入偏好和本轮相关记忆；明确查询记忆时才读取完整列表。
- 笔记查询先在本地排序并附带最多 8 个结果；`search_notes` 支持 `cursor` 继续读取后续结果；会话历史由上下文大小映射到固定上限。
- 桌面与扩展必须使用 `planAssistantTurn()`，不得自行重建工具白名单或步骤预算。
- 模型每次返回的 actions 受剩余工具步骤预算限制；相同工具与等价参数会生成稳定签名，重复调用会停止本轮任务。
- 非标准 JSON 仅抢救已知工具，实际执行仍需经过本轮白名单；推理模型的开头 `<think>` 内容不会展示或参与工具解析。
- 取消、限流、上下文过长与网络错误由共享核心转换为一致且可操作的用户提示。
- 每轮显示模型调用、检索、耗时和 Provider 返回或本地估算的 token；估算值会明确标记。
- `quick_note`、`quick_todo`、`find_note`、`list_todos` 等旧入口保留兼容实现，但新 Prompt 只暴露更清晰的原子工具。

## 新增或修改工具

1. 在两端 `ASSISTANT_TOOLS` 中实现同名、同语义的原子工具；若仅某端可用，应先设计明确的端侧能力声明，不能静默漂移。
2. 在 `tool-policy-core.js` 登记读写等级、事务、CLI 暴露面和工作目录投影。
3. 在 `assistant-skill-core.js` 把工具加入恰当的只读 Skill 或动作能力。不要为了“可达”而加入通用 Profile。
4. 删除操作使用 `access: 'destructive'`，且不得绕过端侧确认。
5. 为工具归属、查询只读边界、动作条件和桌面/扩展副本一致性补测试。
6. 运行：

   ```bash
   npm run verify
   ```

测试会拒绝未登记工具、没有 Skill 归属的活跃助手工具、只读 Skill 中的写工具，以及共享核心副本不一致等情况。完整模块边界见 [架构文档](architecture.md)。
