# 桌面版工作目录为唯一数据源 + 直接文件操作 + 回收站

- 日期：2026-07-01
- 范围：**仅桌面版（Tauri）**。浏览器扩展版保持现状（localStorage 模型），全部改动用 `isDesktopContext()` 门控。
- 状态：设计已确认，待写实现计划。

## 1. 背景与动机

当前存储模型是"双数据源"：`localStorage` 是数据源，工作目录只是**可选的、防抖的双向同步**（`workdirWriteAll` 写盘 / `workdirImportAll` 读盘）。由此产生一系列分歧类 bug：

- **磁盘有文件却不导入**：前期加入的"按 mtime 增量导入"会跳过 mtime 早于上次导入阈值的文件（如从别处拷入、保留旧修改时间的文件），导致这些笔记永远不被导入。
- **笔记本显示为空**：上述漏导入的直接后果。
- **删除笔记本"成功"但磁盘目录还在**：应用不知道目录里那些未导入的文件，删除时只删了自己知道的（空的）内容，磁盘目录因仍有文件而保留。

根因是"两个数据源 + 最终一致同步"。本设计改为**磁盘为唯一数据源、结构性操作即时直接落盘**，从构造上消除分歧。

## 2. 目标 / 非目标

**目标**
1. 桌面版工作目录**强制**，所有笔记/待办/画板以真实文件形式存于该目录。
2. 在软件中新建/删除/移动/重命名 笔记·笔记本·文件夹·待办 = **直接操作磁盘真实文件/文件夹**，不再出现"软件改了、磁盘没改"。
3. 删除统一进 `<工作目录>/回收站/`，软件内可**浏览/恢复/彻底删除**，**30 天**自动清理。
4. 修复"磁盘有文件却不导入"，保证任何在磁盘的笔记文件都能被载入。

**非目标**
- 不改扩展版模型。
- 不改变现有磁盘文件格式（Markdown + frontmatter、`.excalidraw`、`_assets/`、`_marginote/meta.json`）。
- 不做多设备实时同步/冲突解决（仍是"打开时以磁盘校准"）。

## 3. 存储模型

- **磁盘 = 唯一数据源**。内存数组 `notes/todos/notebooks/folders` 为工作副本。
- **localStorage 仅作启动缓存**（秒开首屏），启动后用磁盘全量校准，**磁盘为准**；不再把 localStorage 当权威。
- 结构性写操作 **write-through**：内存改 + 磁盘改在同一操作内完成。
- 正文编辑 **防抖 write-through**（~800ms 停止输入后写该笔记文件；切换笔记/失焦/关闭前立即 flush）。

### 启动流程（desktop）
1. 同步读 localStorage 缓存 → 立即渲染首屏（保留上一版冷启动优化）。
2. 若未绑定工作目录 → 弹**强制选择**（不可跳过）；已有 localStorage 数据则迁移写入所选目录。
3. 绑定后：**全量可靠扫描**工作目录 → 重建权威状态 → 重渲染。
4. 执行回收站 30 天清理。

## 4. 直接文件操作（write-through）

统一封装为一层 `fileOps`（桌面），供 UI 与 AI 工具共用。每个操作**先改磁盘、再改内存、再渲染**（磁盘失败则不改内存并提示）。

| 操作 | 磁盘动作 |
|---|---|
| 新建笔记/待办 | 写新文件到对应笔记本目录 / `待办/` |
| 编辑正文/标题 | 防抖写文件；标题变更→重命名文件 |
| 移动笔记（改笔记本/文件夹） | 移动文件到新路径，删旧路径 |
| 新建笔记本/文件夹 | **立即**在磁盘创建对应空目录（贯彻"直接操作文件夹"；空笔记本目录同时登记在 `_marginote/meta.json` 的 notebooks 里，导入时据此保留空笔记本） |
| 重命名笔记本/文件夹 | 重命名目录 |
| 删除笔记/待办 | 移动文件进 `回收站/` + 记 trash 索引 |
| 删除笔记本/文件夹 | 移动整个目录进 `回收站/` + 记 trash 索引 |

- 需要新增/暴露的 fs 能力：`rename/move`（若无则用 读→写新→删旧 组合）、`mkdir`（建空目录）。桌面 `cmd_workdir_remove` 已支持删目录（`remove_dir_all`）。
- **空目录清理的豁免**：上一版加入的"删除变空目录"逻辑必须**豁免仍对应当前笔记本/文件夹的目录**，否则会误删刚创建的空笔记本目录。只清理"既无文件、又不对应任何当前笔记本/文件夹"的目录。
- AI 工具（create/update/delete/move/batch…）改为调用同一 `fileOps`，避免只改内存不落盘。

## 5. 回收站

- 目录：`<工作目录>/回收站/`。
- 删除时：把文件/整个笔记本目录移入 `回收站/`，用唯一前缀避免重名：`回收站/<uid>__<原文件名>`（目录则 `回收站/<uid>__<原目录名>/`）。
- 索引：`_marginote/trash.json` = `[{ trashPath, originalPath, type: 'note'|'todo'|'notebook'|'folder', name, deletedAt }]`。
- **软件内「回收站」视图**：
  - 列表：名称 + 删除时间 + 剩余天数（30 - 已过天数）。
  - 恢复：移回 `originalPath`（若原路径已被占用则加序号）；重新导入到应用。
  - 彻底删除：从磁盘删除 + 移除索引项。
- **30 天清理**：`deletedAt` 距今 > 30 天 → 删磁盘 + 移除索引。触发时机：启动时 + 打开回收站视图时。
- **导入跳过 `回收站/`**：其中的文件不计入活跃笔记（现有导入已 `!e.path.startsWith('_')`，需再排除 `回收站/`）。

## 6. 导入可靠性修复

- **移除按 mtime 跳过未载入文件的增量逻辑**。
- 新规则：启动全量扫描，**任何在磁盘但应用内不存在（按 frontmatter `id`）的文件一律导入**；mtime 仅用于"已载入且 mtime 未变"的文件跳过重复解析（纯提速），**绝不跳过尚未载入的文件**。
- 结果：外部拷入/旧修改时间的文件都能进；笔记本不再显示空。

## 7. 迁移与冲突

- **首次升级**：无工作目录 → 强制选 → 把现有 localStorage 的 notes/todos/notebooks/folders/images 全量写入；已绑定 → 直接用并校准。
- **冲突**：磁盘存在性为准；同一笔记正文以 mtime 较新者为准（能接收外部编辑）。
- 迁移期间出错要可诊断（`logError`），不静默丢数据。

## 8. 组件边界

- `fileOps`（desktop 专用）：封装 笔记/待办/笔记本/文件夹 的 建/改/移/删 → 磁盘 + 内存。单一入口，UI 与 AI 工具共用。
- `trash`：回收站的 移入/恢复/彻底删/30天清理/索引读写。
- `workdirImport`（改造）：可靠全量扫描 + 排除 `回收站/`；去增量跳过。
- `workdirMigrate`：首次迁移 localStorage → 磁盘。
- 启动编排：首屏缓存渲染 → 强制绑定 → 全量校准 → 回收站清理。

## 9. 测试

离线可测（Node 单测，不依赖 Tauri）：
- trash 索引：移入生成唯一 trashPath、恢复算目标路径（重名加序号）、30 天保留计算（含边界）、彻底删移除索引。
- 导入可靠性：磁盘有而应用无 → 必导入；已载入且 mtime 未变 → 跳过解析；`回收站/` 路径被排除。
- 路径计算：移动/重命名笔记与笔记本的新旧路径、旧路径清理、路径互换不误删、外部文件不误删（沿用已有测试思路）。

桌面端由用户实测：迁移、强制选目录、删/移/重命名后磁盘即时一致、删笔记本后目录进回收站、回收站恢复、30 天清理、外部拷入文件能导入。

## 10. 风险

- 改动面大（所有增删改移路径 + AI 工具 + 启动编排）→ 分步实现、逐步验证。
- 正文防抖落盘：切换/关闭前必须 flush，否则丢最后编辑。
- 强制工作目录改变首启体验：迁移必须稳、可回退（迁移前 localStorage 数据不删，作为兜底）。
- 桌面/扩展双模型：全部桌面改动 `isDesktopContext()` 门控，避免影响扩展。

## 11. 明确不做（YAGNI）

- 扩展版同等改造。
- 实时文件监听（inotify/FSWatcher）；仍是"打开时校准"。
- 多设备冲突合并策略（超出本次范围）。
